# T3：模拟器（MCP Apps 宿主）亲手踩到的坑（2026-10-20）

### The sandbox origin must serve the sandbox page's own bundle
- Tool / API / SDK: @modelcontextprotocol/ext-apps 2.0.3 (examples/basic-host/serve.ts), vite 8.3.4
- Task attempted: Serve the MCP Apps sandbox proxy from its own origin and load an App through it.
- Steps taken: Copied basic-host's serve.ts pattern: the sandbox Express app answers `/sandbox.html` with a CSP header and 404s everything else. Built sandbox.html with Vite (separate HTML entry).
- Expected: The proxy posts `ui/notifications/sandbox-proxy-ready` once its bundle loads.
- Actual: The built page requests `/assets/sandbox-*.js` and `/assets/app-bridge-*.js` from the sandbox origin; both 404 (`net::ERR_ABORTED`), the proxy never posts ready, and the host fails with `Sandbox proxy did not become ready` after 8 s. Playwright: `element(s) not found` for the App iframe.
- Severity: Blocker
- Workaround: Serve `/assets` from the sandbox origin too (`sandboxApp.use("/assets", express.static(join(DIST, "assets")))`), keeping every other path 404. Alternatively inline the sandbox bundle into sandbox.html.
- Actionable suggestion: Say in the basic-host README that a built `sandbox.html` needs its JS/CSS assets on the sandbox origin (or a single-file build) — the example's catch-all 404 is easy to copy verbatim.

### Vitest collects Playwright specs and dies on test.beforeAll
- Tool / API / SDK: vitest 4.1.12, @playwright/test 1.64.1
- Task attempted: Run unit tests with `vitest run` in a package that also has `test/e2e/*.spec.ts`.
- Steps taken: Added the Playwright spec, then ran `npx vitest run` with Vitest's default include (`**/*.{test,spec}.?(c|m)[jt]s?(x)`).
- Expected: Only unit tests run.
- Actual: `FAIL test/e2e/sim.spec.ts` with `Playwright Test did not expect test.beforeAll() to be called here` — the file was imported as a Vitest suite.
- Severity: Minor
- Workaround: Added `vitest.config.ts` with `test.include: ["test/unit/**/*.test.ts"]`.
- Actionable suggestion: Document the default include pattern next to the Playwright integration guide; the naming collision is easy to hit in one package.

### `[hidden]` loses to a class rule with `display: flex`
- Tool / API / SDK: Chromium 156 / CSS
- Task attempted: Keep the demo-clock control hidden when the MCP server has no `GET /demo/clock`.
- Steps taken: Gave the control `class="clock-control"` with `display: flex`, and toggled `element.hidden = true`.
- Expected: The control stays invisible when the server returns 404.
- Actual: It rendered anyway (an empty time input in the top bar): the author rule `.clock-control { display: flex }` beats the user-agent `[hidden] { display: none }`, so the attribute had no effect.
- Severity: Minor
- Workaround: Global `[hidden] { display: none !important; }` in the page stylesheet.
- Actionable suggestion: Prefer a `.is-hidden` class or add the global `[hidden]` rule at the top of any app stylesheet that styles layout containers with `display`.
