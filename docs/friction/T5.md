# T5 friction log — departure board MCP App

### AppBridge must be connected before the App document exists
- Tool / API / SDK: `@modelcontextprotocol/ext-apps` 2.0.3 (`AppBridge`, `App`, `PostMessageTransport`)
- Task attempted: mount the built board into a test host iframe and push a tool result into it.
- Steps taken: created the iframe, set `srcdoc` to the board HTML, then built the bridge and called `bridge.connect(...)`.
- Expected: the App's `ui/initialize` request arrives after the bridge is listening.
- Actual: the board never rendered. `App.connect()` sends `ui/initialize` exactly once (no retry) as soon as its script runs; because the iframe document existed first, that one message was posted before the host had a listener and was lost. `await app.connect()` then hung until its request timeout.
- Severity: Major
- Workaround: connect the bridge to `iframe.contentWindow` **first**, then assign `iframe.srcdoc`. Or use the double-iframe sandbox proxy from `examples/basic-host`, which injects the HTML only after `sendSandboxResourceReady`.
- Actionable suggestion: document the ordering in the AppBridge examples — "connect() before the App document is created" — and/or have `App.connect()` retry `ui/initialize` a few times before giving up.

### The App's auto-resize fights a fixed-size host
- Tool / API / SDK: `@modelcontextprotocol/ext-apps` 2.0.3 (`App` autoResize → `ui/notifications/size-changed` → `AppBridge.onsizechange`)
- Task attempted: render the board inside a fixed 880×550 Echo-style screen.
- Steps taken: mounted the App, wired `bridge.onsizechange` to `iframe.style.height = height + "px"` (the pattern from the examples).
- Expected: the board fills the fixed screen.
- Actual: the App reported 588 px (its content height), the iframe grew to 588 px inside a 550 px screen, and the bottom of the timeline was clipped. When a shorter plan reported 496 px, the frame shrank and left a black band.
- Severity: Minor
- Workaround: a fixed-size host ignores `onsizechange` and keeps the iframe at 100% of its container; the App layout shrinks its own table instead.
- Actionable suggestion: state in the host documentation that `containerDimensions` is a hard constraint for fixed-size hosts and that `size-changed` is advisory.

### vite singlefile output name follows the input path, not the entry name
- Tool / API / SDK: vite 8.3.4 + vite-plugin-singlefile 2.3.4
- Task attempted: build `board.html` → `board/dist/board.html`, and a second entry `test/harness/harness.html` → `test/harness/dist/harness.html`.
- Steps taken: one config with `root: board/` and `input: test/harness/harness.html`.
- Expected: `test/harness/dist/harness.html`.
- Actual: `test/harness/dist/test/harness/harness.html` — Vite preserves the entry's path relative to `root`.
- Severity: Minor
- Workaround: a second config with `root: test/harness/` and `input: harness.html`.
- Actionable suggestion: document that HTML entry output paths are derived from the path relative to `root`; the entry name alone does not set the output name.

### Playwright `locator.evaluate` + tsx: `ReferenceError: __name is not defined`
- Tool / API / SDK: `@playwright/test` 1.64.1 evaluated through `tsx` 4.x
- Task attempted: measure element heights inside the App iframe to debug the clipping above.
- Steps taken: `locator.evaluate((el) => { const row = ... })` from a `tsx` script.
- Expected: the measurements.
- Actual: `ReferenceError: __name is not defined` — esbuild's `keepNames` helper is emitted into the serialized function source, but it does not exist in the page context.
- Severity: Minor
- Workaround: keep the evaluated callback free of inner arrow/function declarations (or run the script through plain `node`).
- Actionable suggestion: Playwright could strip esbuild's `__name(...)` wrappers when serializing, or tsx could disable `keepNames` for evaluated sources.
