# T1：排程引擎的 friction log（AME-851）

本票是纯 TypeScript、零运行时依赖的算法实现，没有碰 MCP SDK / 网络 / 浏览器，因此**没有**协议层的坑。以下两条是亲手踩到并验证过的真实记录，不编造。

### TypeScript refuses an object literal whose optional key is also supplied by a later spread
- Tool / API / SDK: TypeScript 5.9.3 (`tsc --noEmit`, `strict`)
- Task attempted: In a vitest helper, build the `replan()` argument from shared defaults and per-test overrides: `{ ..., now: at("18:20"), ...overrides }` where `overrides` may itself contain `now`.
- Steps taken: Ran `npm --prefix scheduler run typecheck` after writing `test/replan.test.ts`.
- Expected: The later spread wins, as it does at runtime; no diagnostic.
- Actual: `test/replan.test.ts(19,5): error TS2783: 'now' is specified more than once, so this usage will be overwritten.`
- Severity: Minor
- Workaround: Removed the redundant explicit `now` and made the override object always carry `now` (typed as required on the overrides parameter).
- Actionable suggestion: In test helpers, put every default behind the spread and give the overrides parameter a type that requires the keys the helper depends on — TS2783 then never fires.

### Vitest reports "Cannot find module '../src/x'" instead of a missing-implementation failure
- Tool / API / SDK: vitest 4.1.12
- Task attempted: Write the tests first (AGENTS §4.2 step 2) before creating `scheduler/src/`.
- Steps taken: `npm --prefix scheduler test` with `test/` present and `src/` absent.
- Expected: A red test run that names the missing behaviour.
- Actual: All five files fail at import time — `Error: Cannot find module '../src/time' imported from .../scheduler/test/time.test.ts`, `Tests  no tests`. Exit code is non-zero, so it is a usable red run, but no assertion is ever evaluated.
- Severity: Minor
- Workaround: Accepted the red run as the "not implemented yet" evidence, then re-ran after writing `src/` — 39/39 green on the first complete run (all four golden tables matched immediately).
- Actionable suggestion: When writing tests first in TypeScript, stub the module's exported signatures (throwing bodies) so the red run fails on assertions instead of module resolution; the saved output then shows what is missing rather than that nothing exists.
