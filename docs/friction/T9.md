# T9 friction log — demo video pipeline

亲手踩到的坑，格式照 `docs/friction/README.md`。

### `say -v '?'` prints localized voice names, and its en_US list is full of novelty voices

- Tool / API / SDK: macOS `say` (Ventura-era, zh-CN system language), `afinfo`
- Task attempted: pick three distinct English voices (narrator, user, Alexa) on whatever Mac runs the pipeline, without hard-coding voice names that only exist on one machine.
- Steps taken: parsed `say -v '?'` by column; matched the `en_US` locale and picked the first three names.
- Expected: three ordinary en_US voices.
- Actual: the display names carry the system language's suffix, e.g. `Reed (英语（美国）)`, so a naive `^([A-Za-z]+) +en_US` match misses them; and the first en_US entries by that rule included novelty voices (`Fred`, `Albert`, `Bad News`), which sound like jokes in a product demo. Passing the base name and passing the full localized string are not interchangeable across machines.
- Severity: Minor (quality, not failure — but a novelty voice in the final cut is not shippable).
- Workaround: parse the locale column, strip the parenthesised suffix to a base name, keep a preference list (Samantha / Reed / Flo), filter a novelty blocklist, and pass the full name back to `say` via a base→full map; allow `DEMO_VOICE_*` overrides.
- Actionable suggestion: a `say` listing mode that emits stable keys (`name`, `locale`, `sample`) as JSON, and a documented way to request "the default en_US voice" instead of guessing a name.

### Playwright throws away the recording if the browser closes before `video.saveAs()`

- Tool / API / SDK: @playwright/test 1.64.1 (`recordVideo`, `Video.saveAs`)
- Task attempted: record a 165-second session at 1280×720, then save the clip to `out/raw/capture.webm`.
- Steps taken: `const video = page.video(); await context.close(); await browser.close(); await video.saveAs(path)`.
- Expected: the file is written after the context closes.
- Actual: `video.saveAs: Target page, context or browser has been closed` — the clip is finalized when the context closes, but closing the browser invalidates the handle; the whole recording is lost and the pipeline exits before muxing.
- Severity: Major (a 3-minute recording run produces nothing).
- Workaround: call `saveAs()` between `context.close()` and `browser.close()`; keep the browser open until the file exists.
- Actionable suggestion: say this explicitly in the `recordVideo` docs ("save the video after closing the context, before closing the browser"), and make `saveAs()` after browser close report "recording discarded" rather than a generic closed-handle error.

### `page.setContent()` drops the overlays installed with `addInitScript`

- Tool / API / SDK: Playwright 1.64.1 (`addInitScript`, `page.setContent`)
- Task attempted: keep a subtitle bar, a simulated pointer and a "SAMPLE" strip on top of every scene, including the full-screen title and architecture cards.
- Steps taken: installed the overlay once with `context.addInitScript(...)` and injected the cards with `page.setContent(html)`.
- Expected: the overlay stays for the whole recording.
- Actual: every `setContent()` replaces the document, so the overlay is gone on the title card, the architecture card and the end card — the init script only runs on new documents/navigations, not on `setContent`.
- Severity: Minor (visual only; caught in the frame review).
- Workaround: re-inject the overlay after each `setContent()` call and re-render the current subtitle line.
- Actionable suggestion: document that `setContent()` creates a fresh document without init scripts, or give `setContent` an option to run them.

### `ffmpeg-static` ships `ffmpeg` but no `ffprobe`

- Tool / API / SDK: ffmpeg-static 5.3.0 (ffmpeg 6.0), system ffprobe 9.0.1
- Task attempted: make the pipeline self-contained — mux with the bundled ffmpeg and assert the output's duration, resolution and codecs before declaring success (AC-12).
- Steps taken: `require("ffmpeg-static")` for the encoder path, then `ffprobe` for the facts.
- Expected: the same package provides both binaries.
- Actual: `node_modules/ffmpeg-static/` contains only `ffmpeg` (45 MB) — no `ffprobe`. On a machine without a system ffprobe the self-check cannot run, and mixing a bundled ffmpeg 6.0 encoder with a system ffprobe 9.0.1 means the parser has to tolerate two output formats.
- Severity: Minor.
- Workaround: probe with the system `ffprobe` when present and fall back to parsing `ffmpeg -i` output; print which one was used. On this Mac the system ffprobe 9.0.1 was used.
- Actionable suggestion: document the pairing (`ffmpeg-static` is the encoder only) or publish `ffprobe-static` from the same release, so a build can pin both.

### `text-transform: uppercase` leaks into `innerText`

- Tool / API / SDK: Chromium 156 (headless), DOM `innerText`
- Task attempted: read the assistant's latest bubble to use as the spoken line in the recording, stripping the "ALEXA" role label first.
- Steps taken: `const text = await bubble.innerText(); text.replace(/^\s*Alexa\s*/i, "")`.
- Expected: the label is `Alexa` and the regex strips it.
- Actual: the role label is styled with `text-transform: uppercase`, and `innerText` returns the *rendered* text (`ALEXA`), so the case-sensitive strip failed and the TTS read "Alexa Alexa, done — …". `textContent` would have returned the source casing, but it also loses line breaks.
- Severity: Minor (caught in the first audio review).
- Workaround: strip with a case-insensitive regex (`/^\s*ALEXA\s*/i`).
- Actionable suggestion: use `textContent` for data extraction and `innerText` only for what the user sees; if a role label must be inside the same node, keep it in a separate element with `aria-hidden`.
