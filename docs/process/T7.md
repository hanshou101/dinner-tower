## 2. 测试先失败（命令 + 输出）

本票不写产品代码，因此没有「测试先于实现」这一步可以照做；对应的做法是：先写独立探针，**让它跑出 FAIL，再判断是产品的问题还是探针自己的问题**。

第一次跑 `scripts/verify.d/90-proof.sh` 里那支探针，39 条里 1 条 FAIL：

```text
PASS  AC-7 clock 18:00 → isError + 9:50 PM
      text: Too late to serve at 7:00 PM. The earliest I can land everything is 9:50 PM.
FAIL  AC-7 failed plan does not touch the active plan  [steps changed]
PASS  AC-5 turkey +20 @18:20 → serveAt 19:20 / original 19:00
```

定位：`whats_next` 回的 13 个步骤时间其实与表 B 一致，FAIL 来自探针用 `JSON.stringify(stepsMap(plan))` 整体比较——键的顺序跟着步骤排序走，与常量表里的书写顺序不同。改成按键逐条比对后：

```text
PASS  AC-7 failed plan does not touch the active plan
```

产品代码没有改动；这条偏差只发生在探针里。

## 6. 偏差与建议

- **偏差 1：根 README 的 Quick start 走不通（FAIL-1，已交回）**。全新 clone 照 README 走到 `bash scripts/dev.sh`，打开 `http://localhost:8080` 得到 `503 Simulator is not built`；`scripts/dev.sh` 只构建 `board/`，不构建 `sim/`，而它的就绪探针打的是 `/api/config`（一直 200），所以照样打印「Dinner Tower is up」。为了让 AC-8/AC-9 在真实 server + sim 上跑，复验里补跑了 `npm --prefix sim run build`（sim/README 有写、根 README 没写），已在 `docs/04-PROOF.md` §5.1 写清复现命令、原始输出与归属（T6 交付 `dev.sh` 与 Quick start；README 措辞归 T9）。
- **偏差 2：AC-10 本机做不了**。本机没有可用的 OpenAI 相容端点，判定按 SPEC §10 v1.2 引用主控在 macmini2 的真模型实测与 `proof/AC10-macmini2-*.png`，本机只补脚本化端点的 E2E 与未配置提示截图，没有写成本机验过。
- **偏差 3：截图用 `prefers-reduced-motion: reduce` 打开页面**。看板按 §6.4 会关掉翻牌动画，这样图里读到的是最终值；`changes` 高亮 5 秒内截图会出现 TIME 列首字被裁的画面（详见 `docs/friction/T7.md` 第 3 条，量过高亮前后 DOM 几何一致），所以截图都等高亮结束再截。
