## 6. 偏差与建议

- 输入 schema **没有**把 1–8 这类范围写进 JSON Schema（写作 `z.number()`），范围校验在 handler 里做：这样 `update_kitchen({burners:99})` 回的是工具结果 `isError:true`（任务书要求），而不是协议层的 invalid params。范围写进了工具 description 的第一句。
- `store.ts` 里 `activePlan` 的时间存「当日分钟数」整数（与调度器同单位），MCP 对外仍按 SPEC 输出 `"HH:MM"`；T4 在边界转换。字段名与 SPEC §6.3 一字不差。
- `scripts/verify.d/20-server.sh` 在 `server/node_modules` 不存在时先跑 `npm ci`：`.github/workflows/verify.yml` 只有 `bash scripts/verify.sh --ci`，没有 install 步骤；不加这一步，CI 上 typecheck / test 会因找不到 `tsc`、`vitest` 直接 FAIL。这条对 T1/T3 等后面加 `verify.d` 的票同样适用。
- 建议（不属于本票）：`list_dishes` 的 `ovenTempsF` 取的是食谱温度（不含 alt 温度）；若 T4 需要把 alt 温度也展示给用户，改 `catalog.ts` 一处即可。
