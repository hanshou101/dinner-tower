## 6. 偏差與建議

- **沒有測試先行**：見第 2 節。功能與測試都通過，但順序違反 AGENTS §4.2 第 2 步。**建議**：稽核把「順序」與「結果」分開判；若要杜絕，模板可以把 TDD 的紅→綠輸出列為 PR 必附證據。
- **AC-10 沒能真的跑**：這台機器沒有可用的 OpenAI 相容端點（詳見 `docs/friction/T6.md` 第 1 條）。AC-10 的 E2E 已按原句寫好並在 `verify.d/31-agent.sh` 標 `need_local`，有 key 時會自動跑；現在它在 `npm --prefix sim test` 裡是 skip。代理迴圈本身用「腳本化 LLM 端點 + 真實 MCP server」驗證（工具調用、elicitation、結果回填、回覆渲染、系統提示含 SKILL 正文），但**模型自己選對黃金菜單**這件事沒被真模型驗證過。
- **改了 T3 的一行 verify 檢查**：`scripts/verify.d/30-sim.sh` 原本寫死斷言 501 占位的字串，屬於 T3 給 T6 留的臨時占位；不改成「已接上 `createChatHandler`」，`bash scripts/verify.sh` 永遠紅。只改這一行，T3 的其他檢查一字未動。
- **AC-10 的「選 share-oven 後看板渲染」還缺 T5**：`board/` 這個包還不存在，`plan_dinner` 的 `ui://` 資源讀不到，頁面會如實顯示 `Could not render the App: Board UI not built…`（見 `proof/T6-agent-02-conversation.png`）。本票沒有假造看板；E2E 寫成「有 `board/dist/board.html` 就斷言 iframe，否則斷言這句誠實的錯誤」，T5 合併後同一支測試會自動改判看板。
- **動詞「輪」的定義**：`MAX_TOOL_ROUNDS = 6` 指「六次帶工具的回應」，用完之後再發一次**不帶工具**的請求拿文字答案，避免模型在第六輪仍要工具時畫面一片空白。SPEC 只寫「最多 6 輪工具調用」，這裡的解釋是「最多 6 次工具執行」。
- **`/api/config` 多給了 `skill` 與 `agent.model`**：SPEC §6.5 只說系統提示要含 SKILL 正文、未配置要禁用輸入框，沒說正文與模型名怎麼到瀏覽器。選擇由伺服器讀檔、經 `/api/config` 下發（模型名只為了在面板上標示，不是密鑰）。
- **建議（不屬於本票）**：T7 舉證時，AC-10 的 E2E 需要在 `.env` 有真 key 的機器上跑 `set -a; . ./.env; set +a; cd sim && npx playwright test test/e2e/agent.test.ts -g "AC-10"`；同時需要 T5 的 `board/dist/board.html` 才能驗看板那一段。
