```text
[console] error Failed to load resource: the server responded with a status of 404 (Not Found)
```

診斷：`server.ts` 的沙箱來源只送 `sandbox.html`（照 basic-host 的寫法），但建置後的 `sandbox.html` 用 `<script src="/assets/…">` 載 bundle；腳本 404 → 沙箱代理永遠不發 `ui/notifications/sandbox-proxy-ready`，宿主 8 秒後報 `Sandbox proxy did not become ready`。修法：沙箱來源加 `/assets` 靜態路由（只開這一條）。修好後 E2E 兩個測試全綠。

單元測試（11 條）在實作 `src/elicitation.ts`、`src/presets.ts` 之後才寫，沒有紅燈記錄——這是本票的流程偏差，見 §6。

## 6. 偏差与建议

- **測試順序**：E2E 在實作寫完後才第一次跑（紅→綠有真實輸出，見 §2），單元測試沒有紅燈記錄。原因：先把 client/host 的 API 對齊官方 `.d.ts` 與 basic-host 範例，再寫測試。缺口已知，不留「先寫測試」的假記錄。
- **螢幕尺寸 864×540**（16:10），SPEC §6.5 寫「≈880×550」：1280 px 寬扣掉右欄 380 px 與間距後，裝置外框 880 px、內螢幕 864×540；比例與 SPEC 一致，寬度少 16 px。若 T7 認為必須逐像素，需主控放寬右欄或頁寬。
- **sim/package.json 的額外 devDependencies**：`@modelcontextprotocol/server@2.3.1`、`@modelcontextprotocol/node@2.1.1`、`@modelcontextprotocol/express@2.0.2`、`cors@^2.8`、`vite-plugin-singlefile@2.3.4`。理由：測試專用 fixture server 需要 server 端套件；fixture App 要打包成單文件 HTML。版本全部照 SPEC §6.0，沒有新增任何全局安裝（只跑了 `npx playwright install chromium`，任務書已批准）。
- **演示時鐘的自動 `whats_next`**：fixture server 沒有 `whats_next`，E2E 只驗到「控件出現、設定後 POST 成功、時鐘更新」。設定後自動調 `whats_next` 的分支要用真的 dinner-tower server 才驗得到，留給 T7。
- 建議（不在本票範圍）：T6 接 `/api/chat` 時，把 LLM 的串流回覆也接進同一個 feed，不要另開面板。
