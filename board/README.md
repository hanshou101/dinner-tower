# board/ — the departure board MCP App

One self-contained HTML file that turns a `PlanView` into an airport departure
board: `SERVE 7:00 PM` in the header, thirteen numbered flights (steps) in a
five-column table, a timeline strip along the bottom, and — the point of the
whole thing — buttons that call the MCP server themselves.

`board/dist/board.html` is built by `vite` + `vite-plugin-singlefile`: all CSS
and JS are inlined and the file makes **no network requests**. That matters
because the host injects it into a sandboxed iframe.

## Build and test

```bash
npm --prefix board install
npm --prefix board run build        # → board/dist/board.html (single file)
npm --prefix board run typecheck
npm --prefix board test             # build + unit (vitest) + E2E (playwright)
npm --prefix board run test:real    # AC-8 against the real server + simulator
```

`npm --prefix server start` (with `DEMO_MODE=1`) reads `board/dist/board.html`
for `ui://dinner-tower/board.html`; build the board before starting the server.

## What it renders (SPEC §6.4)

- **Header** — `DINNER TOWER` | `SERVE 7:00 PM` (flips when it changes) |
  `NOW 6:20 PM` plus a `DEMO CLOCK` badge when `demoClock` is true.
- **Table** — TIME (`3:30 PM`, 12-hour) | DISH (icon + name) | STEP |
  STATION (`OVEN 1 · 325°F`, `BURNER`, `PREP`, `BURNER + PREP`, `REST`) |
  STATUS (`DONE` dim, `NOW` green pulsing, `NEXT` amber for steps in
  `PlanView.next`, `LATER`).
- **NOW row** — an active step gets a `+10 MIN` button that calls
  `report_delay {target: stepId, minutes: 10}` and repaints from the result.
- **Changes** — rows listed in `PlanView.changes` flash for five seconds and
  their text flips over character by character.
- **Timeline** — from the earliest start to serve time: one lane per oven
  (blocks coloured by temperature and labelled `325°F`), a BURNERS lane and a
  HANDS lane (block opacity and `×N` show how many run at once), a red NOW
  line and an amber SERVE line.
- **Conflict banner** — when `PlanView.conflict` is set, the message plus both
  options; each button calls
  `plan_dinner {dishes, serveAt, option}` so hosts without elicitation can
  still resolve the oven question on the board.

All times are 12-hour. The board is dark-only and does not take host theme
variables. `prefers-reduced-motion: reduce` turns every animation off.

## Contract

The board consumes exactly the `PlanView` from `docs/01-SPEC.md` §6.3 — copied
into `src/types.ts`, no server imports. It is an MCP App: `App` from
`@modelcontextprotocol/ext-apps`, `ontoolresult` → render, `callServerTool` →
re-render. Any MCP Apps host can mount it (simulator, Claude, VS Code).

## Tests

- `test/unit/` — 12-hour formatting, status badges, station text, timeline lane
  maths (vitest, Node, no DOM).
- `test/e2e/` — Playwright, headless. `test/harness/fixture-server.ts` is a
  **test-only** MCP server: it serves `board/dist/board.html` as a `ui://`
  resource, exposes `show_plan` / `report_delay` / `plan_dinner` backed by the
  fixtures, and records every `tools/call` at `GET /__calls`. The harness page
  (`test/harness/harness.html`) is a real host: MCP client over Streamable
  HTTP, the board HTML read from the resource, `AppBridge` in a sandboxed
  iframe, and a DOM log of every `tools/call` the App raises.
- `test/real/` — AC-8 against the real T4 server (`DEMO_MODE=1`) and the T3/T6
  simulator, started by `playwright.real.config.ts`.

Fixtures (`test/fixtures/*.json`) are written by hand from SPEC §6.2.6 tables
A/B/C and the §6.3 shape. Product code never imports them, and they are not
generated by the scheduler — that would make the board test the engine instead
of the board.

## Limits

- The NOW line is hidden when the demo clock falls outside the board window
  (before the first step); the header still shows the clock.
- A conflict banner costs two rows of height, so rows tighten from 25px to 22px
  to keep all thirteen steps and the timeline inside an 880×550 screen.
- The board is a view, not a planner: it renders whatever `PlanView` it is
  given and sends three fixed tool calls. It never computes schedule times.
